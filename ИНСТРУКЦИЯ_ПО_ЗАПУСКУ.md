# Инструкция по запуску проекта после исправления ошибки RuntimeIdentifier

## Проблема
```
The RuntimeIdentifier 'android-x64' is invalid.
RuntimeIdentifier "android-x64" и PlatformTarget "arm64" должны быть совместимы.
```

## ✅ Что было исправлено:

1. ✅ Добавлен MSBuild Target для автоматического исправления конфликта RuntimeIdentifier
2. ✅ Созданы скрипты для полной пересборки проекта
3. ✅ Настроена автоматическая генерация папки `assets`

## 🚀 Варианты запуска:

### Вариант 1: Автоматическая пересборка (РЕКОМЕНДУЕТСЯ)

1. **Запустите скрипт `REBUILD_FIXED.bat`**:
   - Дважды щелкните по файлу `REBUILD_FIXED.bat` в папке проекта
   - Скрипт выполнит полную очистку и пересборку
   - Если возникнут ошибки, подробные логи будут сохранены в `build_log.txt`

2. **Откройте проект в Visual Studio**:
   - Откройте `YessGoFront.sln` в Visual Studio
   - Выберите `net9.0-android` в панели инструментов
   - Выберите эмулятор/устройство (например, "Pixel 7 - API 35")
   - Нажмите `F5` для запуска

### Вариант 2: Исправление проблемы с RuntimeIdentifier

Если проблема все еще возникает:

1. **Запустите скрипт `FIX_RUNTIME_ID.bat`**:
   - Удалит все файлы `.csproj.user`
   - Очистит папки `obj` и `bin`
   - Visual Studio создаст новый `.csproj.user` автоматически

2. **В Visual Studio**:
   - `Build` → `Clean Solution`
   - `Build` → `Rebuild Solution`
   - Выберите правильный эмулятор в панели инструментов
   - Запустите: `F5`

### Вариант 3: Ручная пересборка через командную строку

Откройте командную строку (cmd.exe) и выполните:

```cmd
cd "E:\YessProject — копия\YessGoFrontV2"

REM Очистка
if exist obj rmdir /s /q obj
if exist bin rmdir /s /q bin
dotnet clean -f net9.0-android

REM Удаление .csproj.user файлов
for /r %f in (*.csproj.user) do del /f /q "%f"

REM Восстановление зависимостей
dotnet restore -f net9.0-android

REM Создание папки assets
mkdir obj\Debug\net9.0-android\assets 2>nul

REM Сборка для arm64 эмулятора
dotnet build -f net9.0-android -c Debug -r android-arm64

REM ИЛИ сборка без указания RuntimeIdentifier (Visual Studio выберет автоматически)
dotnet build -f net9.0-android -c Debug
```

## 📋 В Visual Studio:

### Если ошибка RuntimeIdentifier все еще появляется:

1. **Закройте Visual Studio** (если открыт)

2. **Удалите файлы настроек Visual Studio**:
   - Удалите все файлы `*.csproj.user` в папке проекта
   - Или запустите `FIX_RUNTIME_ID.bat`

3. **Откройте проект снова**:
   - Откройте `YessGoFront.sln` в Visual Studio

4. **Выберите правильный эмулятор**:
   - В верхней панели выберите эмулятор, который соответствует архитектуре:
     - **arm64 эмуляторы** (Pixel 7, Pixel 6, etc.) → Visual Studio автоматически выберет `android-arm64`
     - **x86_64 эмуляторы** → Visual Studio автоматически выберет `android-x64`

5. **Очистите и пересоберите**:
   - `Build` → `Clean Solution`
   - `Build` → `Rebuild Solution`

6. **Запустите проект**:
   - `F5` или "Start Debugging"

## ✅ Что делает MSBuild Target:

Добавленный Target `FixRuntimeIdentifierConflict` автоматически:
- Проверяет совместимость `RuntimeIdentifier` и `PlatformTarget`
- Очищает `PlatformTarget`, если он конфликтует с `RuntimeIdentifier`
- Это предотвращает ошибку "RuntimeIdentifier и PlatformTarget должны быть совместимы"

## 🔍 Отладка:

Если проблема сохраняется:

1. **Проверьте логи сборки**:
   - В Visual Studio: `View` → `Output` → выберите "Build" в раскрывающемся списке
   - Ищите строки, содержащие "RuntimeIdentifier" или "PlatformTarget"

2. **Проверьте файл `.csproj.user`** (если он существует):
   - Убедитесь, что там нет жестко заданного `RuntimeIdentifier=android-x64` для arm64 эмулятора
   - Если есть конфликт, удалите файл `.csproj.user` и перезапустите Visual Studio

3. **Проверьте выбранный эмулятор**:
   - Убедитесь, что архитектура эмулятора соответствует используемому RuntimeIdentifier
   - Для arm64 эмуляторов → `android-arm64`
   - Для x86_64 эмуляторов → `android-x64`

## 📝 Важно:

- **Не задавайте RuntimeIdentifier вручную** в `.csproj.user` - Visual Studio выберет его автоматически
- **Выбирайте правильный эмулятор** в панели инструментов Visual Studio
- **MSBuild Target автоматически исправляет конфликты** RuntimeIdentifier и PlatformTarget
